WHY IT EXISTS / 为什么需要

把“手里已有数据”与“证据足以形成正式判断”分开，避免用完整排版掩盖样本不足或来源过窄。

MECHANISM / 实际机制
  1. 01

    checkGate 同时校验有效记录数、独立域名数、来源类型数与锁定的来源策略，不接受单项达标。

  2. 02

    报告生成前再次检查 scope 仍为 allowed，并验证分析 JSON 的必填模块与结构。

  3. 03

    每个 evidence_id 必须能解析到真实记录；原文引用必须在对应记录中逐字存在，且单条引用不超过 8 条。

AUDIT TRAIL / 留下的证据
prepared.json · gate
记录 passed、criteria、reasons 与实际覆盖
analysis.json
只保存 record_id / evidence_ids 与限制项，不复制假链接
report validation
暴露缺失字段、无效证据 ID 与引用不匹配
DECISION / 继续或停止

质量门、报告结构与证据引用全部通过才生成正式报告；否则只交付数据包、覆盖缺口和续采建议。

不足样本不包装成正式结论；政治、战争、军事、武器与情报主题不进入流程。
