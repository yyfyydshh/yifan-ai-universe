# 销售专业助手 v8｜执行 brief

状态：`awaiting-user-confirmation`

## 修改范围

仅修改销售专业助手：

- `SalesCaseStudy` 数据类型与 Sales 项目数据。
- 销售项目详情路由使用的局部交互组件。
- 该组件对应的局部样式。
- Sales 相关 Identity / Showcase 证据文档。

不修改其他六个项目的数据、组件、URL 或视觉表现。

## 数据接口

- `visualKind`：`sales-conversion`
- `turns`：三轮累计上下文，每轮包含：
  - 客户本轮脱敏摘要与累计上下文；
  - 新增事实、未知项与变化原因；
  - MQL 等级和公开简化依据；
  - 需求画像；
  - 数据采集与自动化方案路径；
  - 适用能力与授权资料状态；
  - 回复草稿与目的；
  - 各结果关联的证据句 ID。

## 桌面交互

1. 默认第三轮。
2. 点击或聚焦第 1—3 轮，右侧完整刷新 MQL、五类结果、新增事实与未知项。
3. 左右方向键切换轮次；Home / End 跳转首尾轮次。
4. 点击任一结果，只高亮支撑它的当前及历史客户摘要，并展开“为什么变化”。
5. 第一轮只给需求摘要与关键追问；完整方案和案例保持暂缓。
6. 右侧始终可见“脱敏机制示例”“案例需核验”“回复不自动发送”。

## 移动端

- 顺序：定义 → 轮次选择 → 当前需求摘要 → MQL → 五类结果 → 新增事实 / 未知项 / 人工边界。
- 不绘制跨栏证据线，结果下显示来源轮次标签。
- 320px 起无水平滚动；中英文标题自然换行。

## 动效原语

- 轮次聚焦：边框、透明度与不超过 4px 的位移。
- 状态刷新：右侧内容短淡入。
- 证据回链：相关摘要与来源标签切换透明度。

只修改 `transform` 和 `opacity`；reduced-motion 下取消空间位移与过渡。

## 事实与文案边界

- 主名称为“销售专业助手”，`Sales Copilot` 作为英文别名。
- 标题为“把客户的每一次回复，刷新成下一步转化判断。”
- 项目目标是更快理解数据采集/自动化需求并推进转化，不宣称具体转化率提升。
- 不公开真实行业、客户、站点、字段、数据量、内部评分权重或完整 Skill 规则。
- MQL A 最高、D 最低；示例为 D→C→B，A 因预算、决策链和合规边界未知而未达到。
- 案例来自授权资料库并由销售核验；回复是草稿，不自动发送、报价或承诺实施。
