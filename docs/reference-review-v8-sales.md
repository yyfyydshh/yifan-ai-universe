## 领域校正

- 主任务已改为挖掘客户的数据采集与自动化需求，不再使用线索协作场景。
- 三轮只展示需求信息逐渐完整：初步采集诉求 → 行业、数据与频率 → 采集、清洗、调度、交付及系统/AI 衔接。
- 为保护商业机密，不出现真实行业名称、站点、字段、数据量、客户身份或内部 Skill 规则。

## 审查结论

### 视觉意义

- 不依赖说明文字也能看见“三轮客户回答 → 数据采集需求画像 → 当前转化状态”。
- 第三轮、MQL B 和五类输出形成单一主焦点。
- D→C→B→A 表达需求成熟度变化，并明确 A 尚缺预算、决策链和数据合规边界。

### 事实边界

- 需求画像只呈现已确认的抽象维度，不生成具体行业或客户属性。
- 适用能力与案例资料不写数量，只表示匹配能力方向与授权资料，并保留销售核验。
- 回复明确是用于继续确认数据来源、规模、合规与接口的草稿，绝不自动外发。
- 页面不声称已提升转化率，也不展示实时 Agent 状态。

### 设计一致性

- 延续深石墨、暖象牙 serif、mono 状态标签和低饱和紫焦点。
- 没有玻璃拟态、球体、装饰轨道、假 KPI 或模拟运行成功。
- 结构为 `Turn-Led Conversion State Desk`：轮次控制器直接刷新完整需求与转化快照。

### 单调性与作者性

- 不是同权重卡片墙；左侧是累计回答，中央是语义维度，右侧是一份完整状态快照。
- 中央证据桥只表达行业、数据、频率、自动化程度与系统衔接如何进入分析。
- 点击轮次用于切换累计状态；点击结果用于回看支撑判断的客户回答。

### 可实施性

- 所有文字、图标、MQL 状态、轮次、连线和切换状态都可由 React / CSS 原生实现。
- 参考图不进入生产资产，不依赖 raster 才能成立。
- 移动端可按标题 → 轮次 → 当前需求摘要 → MQL → 五类结果 → 未知项与人工边界自然重排。

## 构建时必须遵守

- 参考图中的 Turn 英文和图标仅为构图语汇，生产页面用一致的中文可访问标签。
- 生产文案使用 `facts.md` 与数据接口中的精确文字，不照抄图片字形。
- 第一轮严格暂缓具体方案与案例匹配；第二轮只形成初步需求画像；第三轮才进入方案评估。
- 具体行业、站点、字段、数据规模和 Skill 内部规则不进入公开演示。
