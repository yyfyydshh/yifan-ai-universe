# v5 参考图生成计划｜第一批项目证据档案

状态：第一步内容与风格已由用户批准；进入第二步参考图生成与审查。此文档只锁定 Sales Copilot、Mintlify 文档站 SOP、金融监管风险监测三个详情 section，不授权页面代码实现。

## 1. 共用 Style Fingerprint

- 画布：1672 × 941 横向网站 section 截图。
- 背景：近黑蓝 `#070B13`；次表面 `#0D121D`；规则线 `#303748`。
- 文字：暖白 `#EADCC5`；弱化文字 `#A49D94`；当前交互使用低饱和紫 `#9C7BEF`；绿色只表达规则条件通过，不表示真实运行状态。
- 字体角色：中文 serif display；干净中文 sans body；英文状态与字段名使用窄体 mono。
- 几何：开放式工作台、细规则线、少量有职责的边框；圆角克制；Lucide 风格细描边图标。
- 动效暗示：阶段聚焦、路径推进、状态切换；不出现实时 Agent、假计时、假 KPI 或装饰性轨道。
- 全局 chrome：参考图可省略站点导航，重点表现详情页下文 section；最终页面复用现有导航、项目 mast 与视频占位。
- 黑名单：随机球体、世界地图、玻璃卡片墙、无含义 node、虚构客户数据、不可读 dashboard、渐变文字、浏览器外壳。

## 2. Sales Copilot｜事实判断与方案路由台

- Archetype：`C0 code-only`；拓扑 `section-specific`。
- 三秒信息：这不是自动替销售做决定，而是把零散沟通整理为可复核判断，并在证据不足时主动停在追问。
- 个人证据：事实/假设/未知分层、机会优先级、单一方案方向、核验材料、人工外发边界；公开仓库仅为脱敏概要。
- 作者性动作：左侧“事实账本”与中部单线路由共享一个决策门；右侧深度解释随阶段切换，不重复节点短说明。
- 主焦点：事实充分与不足两条分支如何改变下一步。
- 阅读路径：证据状态 → 输入分层 → 单线路由 → 人工外发边界。
- 代码安全区：所有文字、控制、状态和路径；无 raster 区域。
- 语义图形：三列账本表示事实归属；单线表示只给一个聚焦方案方向；末端分支表示草稿与人工确认。
- 响应式：桌面为开放式三段工作台；移动端按账本、路由、深度说明依次堆叠。
- 禁止融合：不得把 MQL 评分细则或客户样例烘入参考图；不得用假分数证明能力。

## 3. Mintlify 文档站｜三路径交付控制台

- Archetype：`C0 code-only`；拓扑 `section-specific`。
- 三秒信息：同一套知识工程系统根据从零搭建、旧站迁移、日常维护三种任务切换路径，但都必须经过托管验收和受控发布。
- 个人证据：信息架构、HTML 到 MDX、图片本地化、导航链接、搜索、审核发布与持续维护；公开仓库证明 SOP，简历证明真实项目经历。
- 作者性动作：三条入口轨道在中部汇入共同验收脊柱；选择路径后，阶段与右侧验收清单一起变化。
- 主焦点：`本地验证 ≠ 托管验收` 的双门结构。
- 阅读路径：证据分层 → 路径选择 → 生产链 → 双门验收 → 发布授权。
- 代码安全区：路径 tab、节点、验收差异、产物列表；无 raster 区域。
- 语义图形：三条线表示不同输入路径；汇流表示共用质量规则；双门表示本地与托管分别验证。
- 响应式：桌面横向三路径汇流；移动端为可切换的单条纵向路径。
- 禁止融合：不得把 SOP 仓库描述成生产站完整源码；不得展示虚构文档页截图。

## 4. 金融监管监测｜企业适用性审阅台

- Archetype：`C0 code-only`；拓扑 `section-specific`。
- 三秒信息：监管记录先经过当前批次、全文审阅和企业适用性判断，验证通过后才进入风险报告与投递。
- 个人证据：输入校验、任务快照、全量导出、证据索引、覆盖校验、适用性判断、报告校验和投递防重。
- 作者性动作：中部四轴适用性矩阵成为整条流程的判定中心；任一缺口会把路径导向阻断说明。
- 主焦点：地域、主体、业务活动、时间条件四轴匹配。
- 阅读路径：当前批次 → 语义审阅 → 适用性矩阵 → 报告校验 → 送达或阻断。
- 代码安全区：所有矩阵、状态、证据字段和分支；无 raster 区域。
- 语义图形：四轴交叉代表适用性条件；快照线表示当前运行批次；指纹与回执表示重复投递拦截。
- 响应式：桌面为左流程、中矩阵、右解释；移动端矩阵改为四行状态，不隐藏边界。
- 禁止融合：不得把处罚记录表示为目标企业违法事实；不得将报告描述为法律意见。
