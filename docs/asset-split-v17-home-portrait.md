# v17 首页真人身份窗口素材拆分

## 【首页 Hero】

交互假设：真人照片是可点击的独立媒体；默认半透明，悬停/聚焦增强，点击在原位置显影；移动端点击切换，不打开弹窗。

总判断：需要 1 个图片素材；背景/融合场景 0 个，独立媒体 1 个。其余导航、文字、能力 rail、按钮、星球、轨道和交互全部由代码实现。

| ID | 图片层级 | 复用范围 | 状态 | 内容与边界 | 代码覆盖 | 裁决理由 |
| --- | --- | --- | --- | --- | --- | --- |
| `yifan-portrait-source` | `independent-media` | `section` | `source` | 用户提供原始照片；桌面竖向裁切保留头肩与建筑曲线，移动端宽幅浅景裁切；不得生成、换脸或把文字烘进照片 | 深色调色、透明度、渐隐遮罩、边框、显影状态、按钮语义与响应式裁切均由 CSS / React 负责 | A：真人身份和独立点击要求单独边界；B：摄影必须使用 raster；C：可独立替换、裁切与显影，因此不是背景或融合场景 |

Code-native：

- 姓名、角色定位、价值主张、三段能力 rail、CTA。
- 四项目三轴投影、轨道、拖动、惯性、键盘和 reduced-motion。
- 照片容器、深石墨/紫色调色、35% 默认透明度、60% 悬停/聚焦态、点击完整显影态。
- `button`、`aria-pressed`、清晰的焦点环和“查看本人照片 / 收起照片”辅助文本。

真实来源 / 风险：

- 原始照片由用户提供并明确要求用于主页，来源状态为 `source`。
- 不生成新的脸部、服装、背景或姿态，不删除原图内容。
- 只复制一份版本化网站素材，不覆盖或修改用户原文件。
- 默认透明度不能低到看不清人物；移动端不依赖 hover。

素材预算：1 个独立媒体，0 个生成素材。不存在跨边界阴影、文字烘焙或移动端无法重排的问题。
